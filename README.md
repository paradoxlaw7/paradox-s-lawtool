## 启动与使用

推荐双击本目录的 `打开预览.cmd`：检查现有服务，必要时在后台启动，然后打开 http://127.0.0.1:8766 。桌面 `[约定]` 目录另有 `打开约定预览.cmd` 快捷入口。本机地址只能在这台电脑访问；关机或进程退出后需要重新启动，域名本身不运行此服务。`启动工作台.ps1` 保留为前台启动与诊断入口。需要 Python 3.11+；脚本也可使用本机 Codex 已安装的 Python。直接执行 `python server.py` 的默认端口仍为 8765；可用环境变量 PORT 修改。

1. 新建真实项目，左侧导入 `.docx`、`.md`、`.txt` 文件，或导入文件夹。每个文件最多 3 MB，每次最多 40 个文件。子目录层级按导入路径展示，支持搜索和下载原件。
2. 打开文件，点击“用作业务材料”，或直接在“业务材料”中输入并保存。导入不会自动替换当前项目事实，避免误用附件。
3. 点击“保存并分析材料”，在事实与确认页填写回答及确认人，再点击“确认事实，进入起草”。未明确的事实应如实说明待确认，不需要虚构。
4. 生成两份协议，中央正文可编辑，支持标题、加粗、斜体、列表、保存、Word 导出。左侧切换协议；顶部六步导航显示当前进度；中央主按钮引导下一步，右侧审阅清单承载内部审阅意见。右侧可提问，也可先选中文字再提出修改要求。
5. AI 提案展示修改前后和理由，法务点击采纳后写入正文。手动修改后，过期的 AI 提案不能直接覆盖新正文。存在未保存的材料或协议时，会阻止生成与归档。
6. 依次核对服务协议、隐私政策和审阅意见，并点击各项审阅确认，再记录法务结论并归档。审阅进度保存在当前浏览器，按当前正文及修订轮次区分；正文修改并保存后需重新核对。此进度用于界面引导，不能替代正式法务结论或审批记录。后续从“业务变更与修订”提交进展，以最近定稿生成候选稿；原定稿只读，程序独立计算全文差异。

“示例项目”使用明确标注的预置案例，分析、起草、修订均不调用模型。自由聊天会明确说明这是示例模式，不伪装成模型回答。真实项目未配密钥时不会退回预置答案。

## 模型连接

本机右上角“设置”填写硅基流动 API 密钥、账号可用的完整模型名称，以及输出约束模式。密钥仅存于服务进程内存，重启失效；长期运行用 `.env` 或服务端环境变量配置。

- `auto`：优先 JSON 模式，仅在服务端明确表示不支持该参数时降级为提示词约束。
- `json_object`：明确要求 JSON 对象。
- `json_schema`：严格结构模式，需所选服务和模型支持。
- `prompt`：兼容仅支持普通文本输出的模型，返回结果仍必须通过本地校验。

“模型已配置”只代表有配置，不代表调用验证成功。本轮已完成真实硅基流动调用；结果与性能记录见 [真实模型测试记录.md](真实模型测试记录.md)。单个案例通过不代表所有业务或法律判断均已验证。

## 对原报错的修复

旧版将缺失响应字段、空正文、JSON 解析失败等合并成“模型未返回完整 JSON”，因此无法仅凭该提示判断原始原因。旧版已有输出长度检查，不能把那次错误直接认定为长度上限问题。

新版按分析、服务协议、隐私政策、修订、聊天分别限定任务，避免把 PRD 中的“生成两份协议”当成分析阶段指令。增加输出模式协商、结构校验和一次有限重新生成；明确区分格式错误、字段缺失、空正文、仅推理、长度上限、认证、限流和连接中断。认证、限流和不确定的网络失败不会自动反复调用。

两份协议分别生成，全部成功后才写入项目；其中一份失败不会把半套协议标记为成功，也不会覆盖旧定稿。修复不会靠补括号、删尾段等方式“凑出”法律文书。

修订阶段只要求模型返回条款替换建议，程序核对每段原文在基线中唯一出现、各替换区间不重叠，再组装完整候选稿。未变动条款按原文保留。

模型响应使用持续接收，持续收到内容的长任务不会因固定150秒的整次等待而被中断；连续90秒没有网络响应或单次接收超过600秒时明确失败。收到的片段仅在后台缓冲，完整结果通过校验前不会写入正文。任务进度只展示当前阶段，不伪造百分比。

任务记录保存在数据库，关闭或刷新浏览器不取消后台任务。服务进程重启后，将中断任务标记为失败，需主动重新发起，不自动重复计费。诊断日志仅包含请求编号、任务阶段、模型名称、耗时、长度、完成原因与错误类别，不记录材料正文、模型正文或密钥。

## 数据及能力边界

- 数据保存在 `data/workspace.sqlite3`，原上传文件也存于数据库；备份该数据库时应使用 SQLite backup 或停止服务后复制，不能只复制运行中的主文件而遗漏 WAL。
- 文件夹管理是导入到工作区的副本，不是直接挂载磁盘；保存不自动写回用户原文件，导出时可另存。
- 中央当前是轻量 Word 风格编辑器，WPS 正式内嵌的下一阶段见 [WPS接入方案.md](WPS接入方案.md)。原生 DOCX 导入与重新导入保存文件二进制；未经轻量正文编辑重建时，导出和归档保留其原生版式。当前网页正文提取不展示复杂排版、图片、表格布局、批注和修订轨迹；轻量编辑后的 DOCX 仅支持基础标题、段落、粗斜体，Markdown 表格保留为文字。
- 本版保留单工作区访问口令。没有企业账号、多租户、权限分级、电子签名或可靠实名审批。归档摘要用于检测文本变化，不是专业存证。
- 未接入法律检索、法律知识库或实时法规更新。法务需核验法律适用及引用；结构合规不等于法律结论正确。
- 定期复核是工作台内的待办与结论记录，没有新增邮件或微信定时推送。
- 文档修改在本标签页暂存，点击保存才写入数据库。关闭标签页可能丢失未保存缓存。旧版示例中的历史确认人原样保留，不会重写旧档案。

## 部署与更新

本版沿用 Python + SQLite + Docker + Caddy，没有新增 Node 运行时或前端构建依赖。`Dockerfile` 已包含新增模型网关、错误定义和 Word 导出模块。compose 新增 `AI_RESPONSE_FORMAT` 环境变量。

发布前备份现网数据库和配置；保持原有数据卷，替换应用源码后重新构建镜像。数据库初始化为添加文件表、任务表和索引，不删除项目或定稿。不要用本机测试数据库替换生产库。回滚时恢复旧应用镜像；必要时使用更新前数据库备份。

生产环境继续使用 HTTPS、服务端模型密钥和访问口令。域名和服务器的配置沿用现有部署；本次没有执行线上发布。生产服务不开放网页填写模型密钥。
